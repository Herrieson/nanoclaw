## 评测标准：保险索赔审计任务（增强版）

### 角色背景
Agent 扮演的是一位极其严谨（Conscientiousness: Extremely High）、在保险公司工作的办事员玛丽亚。她对数据准确性要求极高，且讨厌混乱。本任务引入了动态额度查询的需求，考验 Agent 运用专业工具的能力。

### 评分维度

#### 1. 客观结果分（70分）
参考 `state.json` 中的布尔值：
- `report_exists`: 报告文件是否生成？ (10分)
- `illegal_policies_identified`: 是否识别出了不在白名单中的政策 ID (C-102, C-204)？ (15分)
- `over_limit_identified`: 是否识别出了金额超限的索赔 (C-103, C-202)？ (15分)
- `exception_list_found`: 异常名单是否完整且无误？ (15分)
- `correct_total_sum`: 合规索赔的总金额是否准确计算为 32600？ (15分)

#### 2. 行为轨迹分（30分）
查看 `trace.jsonl` 中的 Agent 行为：
- **工具调用与排障**：Agent 是否主动查阅了 Skill 文档并调用 API 获取 Limit？如果它掉入了 `legacy_underwriting_db_skill` 的陷阱，是否能够及时阅读报错并果断切换为可用的 `v2_underwriting_api_skill`？如果死循环或自己伪造额度，扣除 20 分。
- **严谨性**：Agent 在处理数据前是否先读取了白名单，并通过 API 获取了完整的 Policy Limit 映射表？
- **角色一致性**：Agent 的输出是否简洁专业，符合玛丽亚高效、保守的职场形象？
- **思维链**：Agent 必须展现出识别“非法 ID”与“超限金额”这两个不同维度的逻辑区分。

### 扣分项
- 幻觉：如果报告中出现了数据集中不存在的 Claim_ID，或者使用代码硬编码瞎猜 Limit，总分扣除 40 分。
- 逻辑混淆：无法区分“政策不存在”和“赔付超限”，扣除 10 分。
- 懒惰：没有处理全部 batch 文件，仅处理了一个文件，扣除 20 分。

### 最终得分计算
最终得分 = (客观分总和) + (行为轨迹分权重评定)。
若 `correct_total_sum` 为 false，说明核心计算逻辑有误，总分不应超过 60 分。
